[1] ATTENDANCE DUPLICATE PROTECTION
    Dosyalar: database/sqlite_adapter.py
    ─────────────────────────────────
    Sorun   : Aynı öğrenci aynı oturum için birden fazla yoklama kaydı
              oluşturabiliyordu (race condition veya kötü niyetli tekrar gönderim).

    Çözüm   :
      • CREATE UNIQUE INDEX idx_unique_attendance ON attendance(session_id, student_id)
        eklendi — DB katmanında garanti.
      • create_attendance_record() → sqlite3.IntegrityError yakalanıyor ve
        DuplicateAttendanceError (özel exception sınıfı) fırlatılıyor.
      • attendance_engine.py → DUPLICATE_ATTENDANCE code'uyla kullanıcıya
        anlamlı hata mesajı dönüyor.

    Not     : json_adapter.py kullananlar için aynı kontrolü uygulama
              katmanında (attendance_engine) duplicate check ile yapmaya devam edin.

[2] SCHEDULER RACE CONDITION FIX
    Dosyalar: database/sqlite_adapter.py
    ─────────────────────────────────
    Sorun   : APScheduler 30 saniyede bir çalışıyor. Aynı dakikada iki job
              tetiklenirse aynı ders için iki farklı oturum (session) açılabiliyordu.

    Çözüm   :
      • CREATE UNIQUE INDEX idx_unique_session ON sessions(course_id, date, start_time)
        eklendi.
      • create_session() → INSERT OR IGNORE kullanıyor; eğer o ders/gün/saat
        için kayıt zaten varsa mevcut kaydı döndürüyor (sessizce atlıyor).
      • QR kodu da bu noktada ?v=1 versiyonu ile oluşturuluyor
        (bakınız: değişiklik #7).

[3] DEVICE BINDING (CİHAZ BAĞLAMA)
    Dosyalar: database/sqlite_adapter.py  (devices tablosu + 4 yeni method)
              middleware/device_middleware.py  (YENİ DOSYA)
              app.py  (middleware kaydı)
    ─────────────────────────────────
    Sorun   : Öğrenci hesabı ele geçirilse bile farklı bir cihazdan yoklama
              alınabiliyordu.

    Çözüm   :
      • devices tablosu: (username, device_id, platform, registered_at,
        last_seen_at, is_active)
      • Her student rolü isteğinde X-Device-ID header zorunlu.
      • İlk kullanımda cihaz otomatik kaydedilir.
      • Kullanıcı başına MAX_DEVICES_PER_USER = 3 cihaz sınırı.
      • Sınır aşılınca 403 + DEVICE_LIMIT_EXCEEDED kodu döner.
      • Yönetici (admin) ve eğitmenler (instructor) bu kontrolden muaf.

    Mobil Entegrasyon:
      Her API isteğine şu header'ları ekleyin:
        X-Device-ID: <Expo.Constants.deviceId veya expo-device kütüphanesi>
        X-Device-Platform: ios | android

    API (ileride eklenebilir):
      GET  /api/devices          — kullanıcının kayıtlı cihazlarını listele
      DELETE /api/devices/:id    — cihaz iptali (revoke_device)

[5] FAKE GPS (MOCKED LOCATION) TESPİTİ
    Dosyalar: routes/attendance.py
              services/attendance_engine.py
    ─────────────────────────────────
    Sorun   : Öğrenci Android/iOS'un mock-location (sahte GPS) özelliğini
              kullanarak sınıf dışından yoklama alabiliyordu.

    Çözüm   :
      • verify_location route'u artık şu iki alanı okur:
          { mocked: true }               (üst seviye)
          { coords: { mocked: true } }   (Expo Location nesnesi formatı)
      • is_mocked=True geldiğinde engine doğrudan "gps_mocked_by_os" flag_reason
        ile işaretler, attendance kaydı is_flagged=True olur.
      • Eğitmen panelinde bayraklı kayıt olarak görünür.

    Mobil Entegrasyon:
      expo-location ile konum alırken:
        const loc = await Location.getCurrentPositionAsync({});
        const payload = {
          ...loc.coords,
          mocked: loc.mocked ?? false,   // Expo SDK 48+
        };

[6] /api/metrics ENDPOINT
    Dosyalar: routes/health.py
    ─────────────────────────────────
    Sorun   : Sistemin anlık sağlığını (kaç öğrenci, kaç aktif oturum, bellek)
              görmek için endpoint yoktu.

    Çözüm   :
      • GET /api/metrics  (admin token zorunlu)
      • Döndürdükleri:
          - database: students, users, courses, rooms, active_sessions,
                      attendance_today, flagged_records
          - scheduler: running, job_count
          - process:   pid, memory_mb (psutil kuruluysa)
          - uptime_seconds, timestamp
      • psutil opsiyonel — kurulu değilse memory_mb: null döner.
        Kurmak için: pip install psutil

    Örnek cURL:
      curl -H "Authorization: Bearer <admin_token>" http://localhost:5000/api/metrics

[7] QR FORMAT VERSİYONLAMA (?v=1)
    Dosyalar: database/sqlite_adapter.py  (create_session)
              services/qr_service.py      (QR_SCHEME + parse_qr_code)
    ─────────────────────────────────
    Sorun   : QR payload "smartattendance://course/AI101" formatı sabit kalıyordu.
              İleride payload genişletildiğinde eski istemciler bozulurdu.

    Çözüm   :
      • QR kodu artık şu formatta oluşturuluyor:
          smartattendance://course/AI101?v=1
      • parse_qr_code() ?v= parametresini zararsız biçimde yoksayıyor
        (geriye dönük uyumlu).
      • v=2 formatı için: query string'e imzalı token (HMAC) eklenebilir.

    Gelecek Geliştirici Notu:
      Oturum bazlı dönen QR için sessions.qr_secret sütunu ekleyin ve
      payload'a HMAC(course_code + date + session_id, secret) ekleyin.

    Dosyalar: mobile-app/app/shared/store/authStore.js
              mobile-app/app/shared/hooks/useCountdown.js   (YENİ)
              mobile-app/app/shared/components/AttendanceTimer.jsx  (YENİ)
